## 1. Why We're Building This

### 1.1 The Problem

企业的采购、销售、库存、制造、财务、人事等多条业务线各自为政，单据散落在 Excel 和纸质表格里。没有一套统一的系统把这些业务串起来——从采购订单、到货入库、库存管理、销售发货，到财务记账和经营分析，全靠经验和人工对账，出错率居高不下，数据口径也不一致。

### 1.2 What We're Solving

Build a web-based general-purpose ERP system（Rust 后端，crate 名 `erp-server`）covering the full **商品（Item+SKU）主数据、库存、采购、销售、制造质检、财务、人力资源、项目、固定资产、审批流** lifecycle。One system to run the business — 从订单到记账，从仓库到报表。

## 2. Who's Using This

| Role | Job Description | What They Care About |
| ------ | ---------------- | --------------------- |
| **仓库作业** | 收货、发货、移库、盘点、库存查询 | 库存数量、库位、入库/出库是否顺畅 |
| **采购 / 销售** | 采购订单、销售订单、供应商与客户管理 | 可用库存（ATP）、单据状态、合同信息 |
| **财务 / 人力** | 记账、开票、付款、员工薪资 | 会计科目、日记账、发票、考勤与薪资 |
| **制造 / 质检** | 工单执行、质检记录、不合格品处理 | BOM、工单状态、质检结果、NCR 闭环 |
| **管理层** | 看板、BI 分析、经营决策 | 库存周转、销售趋势、财务汇总、供应商绩效 |

It's a **multi-user system** with role-based access (RBAC) — 因为不是所有人都能删除一张采购订单。

## 3. Features

### 3.1 商品主数据 (P0 — Ship Now or Don't Ship)

**FR-ITEM-001: 商品记录 (Item Master Data)**

- **What**: 商品（Item）+ SKU 的 CRUD，全系统唯一业务实体
- **Fields**:
  - SKU（唯一，系统或人工分配，不允许重复）
  - 名称（商品名称）
  - 分类（Category：原材料 / 半成品 / 成品 / 备品备件 等）
  - 单位（Unit：kg / m / pc / 件 等）
  - 规格（Spec：描述性属性，可选，不再承载行业强制字段）
  - 状态（草稿 / 启用 / 停用）
  - 备注、附件（图片、说明书等）
- **Acceptance criteria**:
  - 创建 / 更新 / 删除商品记录
  - SKU 全局唯一，不允许碰撞
  - 可按任意字段组合搜索
  - 单一商品表，不按行业类型拆表

### 3.2 库存管理 (P0 — Ship Now or Don't Ship)

**FR-INV-001: 入库 (Inbound)**

- 支持多种入库类型：采购收货、生产完工入库、退货入库等
- 记录：入库单号、日期、商品明细（数量/批次）、供应商/来源、操作人
- 自动更新库存数量

**FR-INV-002: 出库 (Outbound)**

- 支持多种出库类型：销售发货、内部领用、移库等
- 记录：出库单号、日期、客户/去向、商品明细、操作人
- 支持批量出库与按 SKU 精确出库

**FR-INV-003: 库存查询与盘点**

- 实时库存查询：按商品、分类、库位、仓库筛选
- 出入库流水：每个商品的完整移动轨迹
- 盘点：生成盘点单、录入盘点结果、产出差异报告

**FR-INV-004: 库位 (Location)**

- 分层库位管理：仓库 → 库位
- 商品绑定库位，支持库位转移

**FR-INV-005: 库存预留 (Reservation / ATP)**

- 为销售订单（或工单）预留可用库存
- 提供 Available-to-Promise (ATP) 可用量视图

### 3.3 制造与质检 (P1 — Should Have)

**FR-MFG-001: BOM 与工单**

- 维护商品 BOM（物料清单）
- 按 BOM 下达工单，跟踪生产进度，工单按 BOM 消耗商品

**FR-MFG-002: 质检 (Inspection) 与不合格品单 (NCR)**

- 工单关联质检记录：检验项目、结果、日期、检验员
- 质检不通过时创建不合格品单（NCR），跟踪纠正闭环

### 3.4 采购与销售 (P1 — Should Have)

**FR-PUR-001: 采购**

- 创建、审批、跟踪采购订单
- 供应商管理（名称、联系人、资质等）
- 采购收货关联采购订单，到货即入库

**FR-PUR-002: 采购申请与采购报价**

- 内部采购申请（Requisition）流转
- 供应商报价（Supplier Quote）记录与比价

**FR-SALE-001: 销售**

- 创建、审批、跟踪销售订单
- 客户管理
- 销售发货自动扣减库存
- 展示 Available-to-Promise (ATP)，避免超卖

**FR-SALE-002: 销售报价与客户信用**

- 向客户提供销售报价（Customer Quote）
- 客户信用（Customer Credit）额度管理

**FR-CONTRACT-001: 合同**

- 采购合同 / 销售合同基础信息
- 合同关联到订单

### 3.5 审批流 (P1 — Should Have)

**FR-WF-001: 审批流引擎**

- 审批流定义（节点/条件配置）
- 审批流实例与审批任务（待办）
- 采购订单、销售订单、采购申请等单据接入审批流

### 3.6 数据导入/导出 (P1 — Should Have)

**FR-IO-001: 导入**

- 批量导入商品数据（Excel / CSV）
- 导入时校验格式与必填字段
- 报告导入成功/失败行数与原因

**FR-IO-002: 导出**

- 查询结果导出为 Excel / CSV
- 预置报表：库存汇总、出入库明细等

### 3.7 搜索与筛选 (P0 — Ship Now or Don't Ship)

**FR-SEARCH-001: 多维度搜索**

- 组合筛选：SKU、名称、分类、单位、规格、状态、库位等任意组合
- 模糊搜索（部分 SKU、名称等）
- 分页返回结果

### 3.8 全流程追溯 (P0 — Ship Now or Don't Ship)

**FR-TRACE-001: 生命周期追溯**

- 记录每个商品从入库到出库的每一次操作
- 记录每次编辑：谁改了什么字段、什么时候
- 按 SKU 查看完整生命周期

### 3.9 人力资源 (P1 — Should Have)

**FR-HR-001: 员工与部门**

- 员工档案、部门组织结构

**FR-HR-002: 考勤 / 薪资 / 劳动合同**

- 考勤记录、薪资发放记录、劳动合同管理

### 3.10 财务管理 (P1 — Should Have)

**FR-FIN-001: 会计科目与日记账**

- 会计科目维护、日记账分录记录

**FR-FIN-002: 发票与付款**

- 发票（开票/收票）记录、对外付款记录

**FR-FIN-003: 试算平衡**

- 借贷平衡校验的财务报表

### 3.11 项目与固定资产 (P2 — Nice to Have)

**FR-PROJ-001: 项目与 WBS**

- 项目维护、WBS 层级分解、预算管理

**FR-ASSET-001: 固定资产**

- 固定资产登记、直线法折旧、资产处置

### 3.12 通知与门户 (P2 — Nice to Have)

**FR-NOTIF-001: 通知**

- 通知收件箱、通知模板、通知偏好设置

**FR-PORTAL-001: 门户**

- 门户账户（Party）管理：客户/供应商在门户中的登录身份

### 3.13 BI 分析与系统管理 (P1 — Should Have)

**FR-BI-001: BI 分析**

- 销售趋势、库存价值、财务汇总、供应商绩效等聚合报表

**FR-SYS-001: 用户与权限**

- 用户管理，RBAC（角色 + 权限 + 部门，可选租户）
- 不同角色看到不同菜单和按钮

**FR-SYS-002: 操作日志**

- 记录用户登录、数据修改等关键操作
- 日志可查询、可导出

## 4. Non-Functional Stuff

### 4.1 Performance

| Metric | Target |
| -------- | -------- |
| 单页查询响应 | ≤ 2 秒（10 万条以内） |
| 数据导入 | 10 万条 ≤ 60 秒 |
| 并发用户 | ≥ 20 同时在线 |
| 可用性 | 99.5%（年停机 ≤ 44 小时） |

### 4.2 Data Volume

- 商品主数据：≥ 10 万 SKU
- 库存变动日志：百万级
- 存储：SQLite3（连接串 `sqlite://data/erp.db?mode=rwc`，WAL 模式，索引设计合理）

> **Heads up**: SQLite3 适合单实例 / 低并发场景。对多用户 Web 应用，确保开启 WAL 模式并正确配置连接池。连接串固定为 `sqlite://data/erp.db?mode=rwc`，数据库文件位于 `data/erp.db`。

### 4.3 Internationalization & Units

- **UI 语言**：中文和英文，可切换
- **单位体系**：商品通过「单位」字段管理（kg / m / pc 等），单位换算通过前端 unitStore 处理
- 输入可在单位间切换；存储与商品单位字段保持一致

### 4.4 Security

- 密码使用 Argon2id 哈希（不是 bcrypt，也不是明文——显然）
- 破坏性操作（删除、关键修改）需确认
- API 认证走 JWT
- 生产环境必须 HTTPS

### 4.5 Maintainability

- Rust 类型系统在编译期捕获大量错误
- 模块化架构，层级边界清晰（handler → service → repository）
- 后端暴露 REST API，前端通过 HTTP 消费
- API 文档：OpenAPI / Swagger

### 4.6 Stack Choices

| Layer | Pick | Why |
| ------- | ------ | ----- |
| **Backend** | Rust + Axum + SQLx（crate `erp-server`） | Axum 是 Rust 生态最主流的异步 Web 框架；SQLx 编译期检查 SQL，`sqlite` feature 原生支持 SQLite3 |
| **Database** | SQLite3（`sqlite://data/erp.db?mode=rwc`，WAL） | 零配置、单文件数据库，规模足够；37 个历史迁移文件将重写为 SQLite 语法并删除管材表 |
| **Frontend** | React 19 + Ant Design 5 + TanStack Query 5 + Zustand 5 | React 成熟；Ant Design 企业级组件开箱即用；TanStack Query 管理服务端状态缓存；Zustand 管理客户端状态 |
| **API** | JSON REST | 标准、朴实、兼容一切 |

## 5. 商品主数据规范 (Item Master Data Reference)

> 商品（Item）是全系统的唯一业务实体，SKU 是其唯一业务编码。这里定义主数据的通用约定，取代原钢管时代的行业字段。

### 5.1 SKU 编码规则

| 规则 | 说明 | 示例 |
| ------ | ------ | ------ |
| 自动生成 | 系统按 `{分类码}-{年月}-{序号}` 生成 | `FG-202608-0001` |
| 人工指定 | 允许手工录入，但必须全局唯一 | 企业自有编码 |
| 唯一性 | 全系统唯一，禁止碰撞 | — |

### 5.2 商品分类 (Category)

| 分类 | 说明 |
| ------ | ------ |
| 原材料 | 采购入库的原料 |
| 半成品 | 制造过程中的中间产物 |
| 成品 | 可直接销售的最终商品 |
| 备品备件 | 维修、耗材类商品 |

### 5.3 单位 (Unit)

`kg` / `m` / `pc` / `件` / `箱` / `L` —— 商品单位在分类下统一维护，跨单位换算由前端 unitStore 处理。

### 5.4 规格 (Spec)

规格为描述性自由文本（如「尺寸、材质、型号」），**不承载任何行业强制字段**。

### 5.5 商品状态

| 状态 | 说明 |
| ------ | ------ |
| draft | 草稿，不可交易 |
| active | 启用，可采购/销售 |
| disabled | 停用，不再交易 |

## 6. Data Model (First Pass)

### 6.1 Core Entity Relationships

```
                    ┌──────────────────────┐
                    │     Item (商品/SKU)    │  ← 唯一业务实体，单表
                    └──────────┬───────────┘
                               │
Supplier ──→ PurchaseOrder ──→ InboundRecord ──→ Item ──→ OutboundRecord ──→ Customer
                     ↑                                              │
                Contract(采购)                                   SalesOrder
                     │                                              ↑
                     └──────────────────────────────────────────────┘

Item ──N:1── Location（仓库 → 库位）
Item ──N:1── InventoryLog（库存变动审计）
WorkOrder ──N:1── Item（BOM 消耗）──1:N── Inspection（质检）── NCR
Supplier ──1:N── PortalAccount（门户账户）
```

### 6.2 Main Entities

| Entity | What It Is | Key Fields |
| -------- | ----------- | ------------ |
| **Item** | 商品主数据 | id, sku(unique), name, category, unit, spec, status, notes, attachments, created_at, updated_at, deleted_at |
| **Location / Warehouse** | 库位 / 仓库 | id, warehouse_id, code, description, max_capacity, current_usage |
| **Supplier** | 供应商 | id, code, name, contact_person, phone, email, address, qualification, score |
| **Customer** | 客户 | id, code, name, contact_person, phone, email, address, credit_limit |
| **PurchaseOrder** | 采购订单头 | id, order_no, supplier_id, order_date, status, total_amount, currency, contract_id |
| **PurchaseOrderItem** | 采购订单明细 | id, order_id, item_id, quantity, received_quantity, unit_price |
| **SalesOrder** | 销售订单头 | id, order_no, customer_id, order_date, status, total_amount, currency, contract_id |
| **SalesOrderItem** | 销售订单明细 | id, order_id, item_id, quantity, delivered_quantity, unit_price |
| **InboundRecord / Item** | 入库单头/明细 | id, record_no, inbound_type(purchase/production/return), order_id, supplier_id, approval_status, items[] |
| **OutboundRecord / Item** | 出库单头/明细 | id, record_no, outbound_type(sales/transfer/scrapped), order_id, customer_id, approval_status, items[] |

| **WorkflowInstance** | 审批流实例 | id, definition_id, business_type, business_id, status |
| **WorkflowTask** | 审批任务 | id, instance_id, node_key, assignee_id, status, comment |
| **Employee** | 员工 | id, employee_no, name, department_id, position, phone, email, hire_date |
| **Attendance / Salary / LaborContract** | 考勤 / 薪资 / 劳动合同 | 各自独立表，关联 employee_id |
| **Account / JournalEntry / Invoice / Payment** | 会计科目 / 日记账 / 发票 / 付款 | 独立表，财务四件套 |
| **Project / WBS / BudgetItem** | 项目 / WBS / 预算 | 独立表，project_id 关联 |
| **FixedAsset / Depreciation / Disposal** | 固定资产 / 折旧 / 处置 | 独立表，asset_id 关联 |
| **Notification** | 通知 | id, user_id, title, content, read_at, template_id |
| **PortalAccount** | 门户账户 | id, party_type(customer/supplier), party_id, username, password_hash |
| **User / Role / Permission** | 用户 / 角色 / 权限 | 独立表，RBAC 三件套 |
| **OperationLog** | 操作日志 | id, user_id, username, action, target_type, target_id, detail(JSON), ip_address, created_at |
