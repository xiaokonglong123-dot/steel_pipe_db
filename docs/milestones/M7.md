## 与设计文档的偏差（已记录，均有理由）

| 偏差 | 原因 |
| --- | --- |
| 数据库 PostgreSQL → SQLite | 单机局域网负载未触达写瓶颈，换零运维；代价是放弃多实例 |
| Jinja2 SSR → JSON API + SPA | 前后端分离是明确选择；模板资产按 token 层移植 |
| 审计 action `check` → `check_confirm` | 与 `check_create`/`check_recover` 命名一致，语义更清楚 |
| `forced_intake` 审计 | 旧设计标注"未实现"，本轮补齐 |
| 库位重新启用 | 旧实现单向停用，本轮补齐 |
| 盘盈先校验后写 | 旧实现依赖整事务回滚，新实现错误更早、更明确 |
