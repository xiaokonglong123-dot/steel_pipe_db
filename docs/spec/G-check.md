# G — 盘点规格

来源：`tests/test_check.py`（567 行）、设计 §5.3、旧 `check_service.py`。

| # | 规格 | 状态 |
| --- | --- | --- |
| G1 | 建单要求库位存在且启用；单状态 `open`；建单**不**写审计 | ✅ M4 |
| G2 | 逐根结论只接受 `ok` / `missing` / `moved`；管子必须仍在盘点库位且 `in_stock` | ✅ M4 |
| G3 | `moved` 必须给实际位置，且与盘点库位不同、目标存在且启用 | ✅ M4 |
| G4 | 同一盘点单同一根管子重复核对 → 覆盖结论（不产生两条） | ✅ M4 |
| G5 | 盘盈登记只暂存实际信息（`surplus_data`）；确认时才校验合规 | ✅ M4 |
| G6 | 确认在**单事务**里应用全部差异；任一项失败整体回滚，session 保持 `open` | ✅ M4 |
| G7 | 确认产出 1 张 `check` 单据 + 每条差异一条明细；写 1 条 `check_confirm` 审计（含 missing/moved/surplus 计数） | ✅ M4 |
| G8 | 盘亏损 `used_count -1` 并把管子置 `missing`；移库两侧 ±1；盘盈 `+1` | ✅ M4 |
| G9 | 只有 `open` 能被确认或取消；已处理 → `409` | ✅ M4 |
| G10 | 取消不改动库存、不写审计 | ✅ M4 |
| G11 | 找回：`missing` → `in_stock`，`used_count +1`，写 `check_recover` 审计；非 `missing` → `409` | ✅ M4 |
| G12 | 盘盈走与入库相同的写路径（含类型扩展表） | ✅ M4 |

## 与旧实现的差异

1. 旧实现确认时对盘盈逐条 `_insert_tube_with_compliance`，失败依赖整个事务回滚；新实现先做完全部合规校验再开写事务，错误信息更早、更明确（HTTP `422` 而非 `500`）。
2. 旧实现的 `cancel` 无 `cancelled` 状态之外的语义；新实现复用同一状态机并对"已处理"返回 `409`。
