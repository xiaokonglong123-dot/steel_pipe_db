# 行为规格

编号保留用于测试和需求追溯。本文描述当前目标行为，不再记录旧实现修复过程；请求/响应结构以 `openapi.json` 为准。

## A — 认证与会话

| 编号 | 行为 |
| --- | --- |
| A1 | 口令使用 argon2id PHC（`m=19456,t=2,p=1`）；随机盐；损坏哈希不得导致 panic |
| A4 | access token 为 HS256，TTL 15 分钟，包含用户、角色、会话版本和过期时间 |
| A5 | refresh token TTL 30 天，包含 UUID jti，不含角色 |
| A6–A8 | 篡改、异密钥、非法算法、过期和非法用户 ID 一律拒绝；过期宽限为 0 |
| A9 | 每次认证检查用户启用状态和会话版本，不一致返回 `401` |
| A10 | 登录下发 access、refresh httpOnly cookie 及 CSRF cookie，`SameSite=Lax` |
| A11 | 未认证 API 请求返回 `401` JSON；HTML 导航跳转登录页 |
| A12 | 写请求必须提供匹配 CSRF cookie 的 `X-CSRF-Token`，否则 `403` |
| A13 | access 过期且 refresh 有效时，前端静默刷新一次并重放请求 |
| A14–A16 | 登出吊销 refresh；refresh 成功必须轮换；旧 refresh 不得重复使用 |
| A17–A21 | 用户名 300 秒内第 10 次失败锁定 300 秒并写一条审计；IP 60 秒内 5 次失败后限流；成功登录清除用户名失败记录 |
| A23 | 限流记录存 SQLite，重启后仍有效；默认只信任 socket 对端地址 |
| A24 | JWT 密钥缺失或短于 32 字节时拒绝启动 |

## B/C — 权限与用户

| 编号 | 行为 |
| --- | --- |
| B1 | 未登录不能访问业务接口；查看者只读 |
| B2 | 入库、出库、调拨、质量、导入及盘点登记要求操作员以上 |
| B3 | 目录管理、用户管理、软删除、审计查看/校验及盘点确认要求管理员 |
| C1 | 管理员创建用户；用户名唯一，密码 8–256 字符；操作写审计 |
| C2 | 改密递增会话版本，使现有会话失效；停用用户不能认证 |
| C3 | 不能停用自己或移除最后一个启用的管理员 |

## D — 库存

| 编号 | 行为 |
| --- | --- |
| D1 | 入库几何或编号非法返回 `400`，重复编号 `409`，成功 `201` |
| D2–D3 | 出库写入状态和时间；重复或非在库出库 `409`，不得产生部分副作用 |
| D4–D5 | 批量出库去重、单事务、单单据、逐根审计；任一根失败整体回滚；空批次 `400` |
| D6–D7 | 并发出库、调拨不得超卖或造成计数漂移；`used_count` 可按实际在库记录修复 |
| D8 | 同库位调拨 `400`，目标不存在/停用 `400`，源非在库 `409` |
| D9 | 问题管出库/调拨需管理员；报废管禁止；SQL 同时防止软删/报废绕过 |
| D10 | 质量标记不改变库存状态，写一条审计 |
| D11–D12 | 软删保留记录，默认隐藏；在库软删释放计数 |
| D13–D14 | 详情包含类型参数和流转历史；单据历史独立于管子记录 |
| D15–D16 | 停用库位不得接收库存；入库必须存在对应钢级标准 |

## E — 合规

| 编号 | 行为 |
| --- | --- |
| E1–E5 | 固定输出钢级、壁厚、外径、长度、筛管参数五项检查；无对应标准的可跳过项需说明原因 |
| E6 | 无匹配标准规格返回 `422`，不得跳过校验 |
| E7 | 强制入库要求管理员，额外记录 `forced_intake` |
| E8 | 强制入库的 `compliance_pass=false` 必须落库 |

## F — 审计与运维

| 编号 | 行为 |
| --- | --- |
| F1–F4 | 哈希使用 `sha256(prev‖action‖detail‖ts)`；创世值固定；业务与链尾同事务提交或回滚 |
| F5–F7 | 分批校验跨批连续，能检出篡改、断链和链尾不一致 |
| F8–F9 | 每种业务写按约定写审计；detail 为稳定紧凑 JSON |
| F10 | `audit verify` 在一致性快照中校验全链，不将并发新增日志误判为损坏 |
| F11 | `reconcile` 修复计数漂移并写审计 |
| F12 | 审计列表的筛选与总数使用同一条件，游标按 id 稳定分页 |

## G — 盘点

| 编号 | 行为 |
| --- | --- |
| G1 | 建单要求库位启用，初始为 `open`，不写审计 |
| G2–G4 | 明细结论限定为 ok/missing/moved/surplus；普通核对必须在当前库位在库范围内；重复核对覆盖 |
| G5 | 盘盈先暂存，确认时校验合规；位置异常目标必须启用 |
| G6–G8 | 确认原子应用全部差异，生成单据与一条确认审计；失败保持 `open` 且无部分写入 |
| G9 | 关闭后不得确认、取消或修改明细；不存在返回 `404`，已关闭返回 `409` |
| G10 | 取消不改变库存，不写审计；取消前已登记的明细作为历史保留 |
| G11 | 找回只允许盘亏管，恢复在库和计数并写审计 |

## H — 导入

| 编号 | 行为 |
| --- | --- |
| H1 | 必须有编号、类型、外径、壁厚、长度、钢级、厂家、库位列；缺列整体 `400` |
| H2 | 逐行返回成功和失败；合法行可成功，不要求整批回滚 |
| H3 | 超过 10,000 行整体 `400`，不得写入 |
| H4–H5 | 支持 UTF-8 BOM 及类型扩展等可选列 |
| H6–H7 | 与单根入库使用相同合规门；筛管参数缺失时该行失败 |
| H8 | 请求体超过配置上限返回 `413` |
| H9 | 导入要求操作员以上和有效 CSRF |

编号沿用旧规格索引，未使用的旧编号不再单列。新需求应先更新本文件和对应测试，再实现。
